# Technical terms

The project uses these technical terms consistently.
The reports apply ASD-STE100 sentence structure.
They do not certify compliance with the complete official ASD dictionary.

| Term | Meaning |
| --- | --- |
| Adapter | Software that converts images and policy actions to the external client interface |
| Asset | A game or MOD data file |
| BC | Behavior cloning, which trains a policy from observation/action examples |
| Checkpoint | A file that stores trained model parameters |
| Client | The Zandronum program that presents the player's game |
| DELTA action | A numeric engine action for a change in movement or aim |
| Digest | A SHA256 value that identifies file contents |
| FOV | Field of view |
| Frame | One captured image with its dimensions and timestamp |
| HUD | The information display visible to the player |
| Input lease | A limited period during which the controller may hold inputs |
| Inference | A model computation that produces an action from an observation |
| IWAD | The base archive selected with the engine's `-iwad` argument |
| LSTM | A recurrent network that retains state between observations |
| MOD | A package that changes or adds game content |
| Observation | The information that the policy receives before an action |
| OS input | Normal keyboard or mouse events sent through the operating system |
| Pitch | Vertical aim |
| Policy | A rule or model that selects an action from an observation |
| PPO / APPO | Proximal Policy Optimization and an asynchronous PPO implementation |
| RL | Reinforcement learning, which changes a policy from interaction rewards |
| SFT | Supervised fine-tuning |
| Stock client | An official client whose executable and engine files remain unchanged |
| Takeover | The user stops AI input and controls the player |
| Tick | One game simulation step. The baseline tests assume 35 ticks per second. |
| Wrapper | Software that presents an existing system through a training interface |
| Yaw | Horizontal aim |
