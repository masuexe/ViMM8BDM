# Version-agnostic PK3 extraction and Colab GPU training

The detector training pipeline now extracts upright character views and foreground projectile or hit-smoke occluders from any ordered PK3 stack and packages them into a self-contained `.tar.gz` training bundle for local or Google Colab GPU execution.

## Version-agnostic PK3 sprite and occluder resolution

Different MM8BDM releases store base skin sprites under different prefixes.
`MM8BDM-v6a.pk3` stores Cutman skin frames under `CUTM`, whereas `mm8bdm-v6b.pk3` and `mm8bdm-v6c.pk3` declare `sprite = $CUT` in `SKININFO.txt` and store frames `A` through `H` as `$CUTA1.PNG` through `$CUTH8H2.PNG` while keeping `CUTMI` and `CUTMJ`.
`build_bank` in `src/vimm8bdm/sprite_synthesis.py` now parses `SKININFO` and `SKININFO.txt` across the supplied PK3 load order and normalizes both `CUTM` and `$CUT` frames so later addon packages override earlier packages.
Full `v6a` Gondola stacks (`MM8BDM-v6a.pk3` plus `classes-v9fh.pk3` and `gondolapatchv2.7h2.pk3`) supply all 17 upright poses (`136` views); `classes-v9fh.pk3` and `gondolapatchv2.7h2.pk3` target `MM8BDM-v6a.pk3` and cannot be launched with `mm8bdm-v6b.pk3`.
Base-only `v6b` stacks (`mm8bdm-v6b.pk3` plus `8bdm-v6b-miscfixes-v6.pk3`) can pass `--allow-partial-poses` to extract the eight upright base poses (`64` views), and future `v6b`-compatible class/Gondola releases will resolve `$CUT` base frames alongside addon frames automatically.

`build_occluder_bank` extracts foreground projectile and hit-smoke sprites (`BUST`, `BUS2`, `CBUS`, `MBU2`, `MMDX`, `MMFX`, `MXP1`, `MXP2`, `MXP3`, `MXP4`, `NEDR`, `PCOI`, `RCTC`, `RCUT`, `W_0B`) across the same PK3 load order.
When `build_dataset` runs with `--profile occlusion` and `--occluders`, `composite` places foreground projectile or explosion sprites either partially in front of the target body (updating the ground-truth box to the remaining visible body pixels) or as separate foreground distractors in the scene, while `_overlay_occluder_on_annotated_image` augments existing mixed datasets with left/right/bottom partial occlusions (including lower-body Mega Buster clipping) and MM8BDM yellow hit-flash linear blends (`RGB' = (1 - alpha)*RGB + alpha*(255, 255, 0)`).

## Post-attack occlusion grace, width-scaled association, bounded horizontal search, bounded combat strafe, and visual patrol in `StableAim` and `BodyAimPolicy`

In `runs/body-aim-4` and `runs/body-aim-5`, single-frame self-projectiles and hit smoke immediately after a tap-fire pulse briefly occluded the target, and close/medium-range strafing or camera turns shifted consecutive boxes by `50-155 px` (`IoU < 0.1`) or varied partially occluded box area by up to `0.35x-2.65x`.
`StableAim` now associates consecutive single-candidate frames (`interval <= 0.2 s`) when either `1/3 <= w*h/(pw*ph) <= 3` or (`0.5 < h/ph < 2` and `0.18 <= w*h/(pw*ph) <= 4` for projectile/flash partial horizontal occlusions) and either `IoU >= 0.1` or center displacement is at most `max(96, 1.35 * max(w, pw))` pixels.
When `enable_attack=True`, `StableAim` holds the prior target box and match count for at most one missing frame (`reason="post_attack_occlusion"`, `interval <= 0.2 s`) immediately after a frame that pulsed `attack=True`, advances the tracker timestamp to the occluded frame, and allows up to `max(144, 2.0 * max(w, pw))` pixels of two-frame displacement when the target reappears on the next frame (`interval <= 0.2 s`).
The occluded frame still emits `Action()` (zero mouse motion and `attack=False`).
When `enable_search=True` (`--enable-search`), `StableAim` records the horizontal side of the most recent valid single candidate (`search_direction = -1` when `x + w / 2 < width / 2`, else `1`), widens the horizontal tracking rate limit to `160 * dt` (`16 px/frame`), waits one `missing_target` frame (`missing_streak == 1`) with zero motion, and on consecutive missing frames `2 <= missing_streak <= search_limit` (`search_limit = 8` when `enable_patrol=True`, else `120`) emits a bounded horizontal-only turn `Action(mouse_dx=16 * search_direction, mouse_dy=0, attack=False)` (`reason="search_target"`, `matches=0`).
When `enable_patrol=True` (`--enable-patrol`) and `missing_streak` exceeds the initial horizontal search window (`missing_streak > 8` with `enable_search=True`, or `missing_streak > 1` without `enable_search`), `StableAim` returns `reason="patrol_target"` (`matches=0`) and `BodyAimPolicy` delegates the frame to `VisualNavigationPolicy(max_turn_step=16)` with `turn_direction = tracker.search_direction` (`settle` -> `forward` holding `'w'` -> bounded `16 px/frame` directional `turn` escape upon `static_view` or `reduced_image_change`).
During `track_target` with `enable_patrol=True`, `StableAim` also regulates engagement distance via `range_key`: adding `'w'` forward approach when `w * h < 4500`, maintaining pure lateral `'a'`/`'d'` strafe when `4500 <= w * h <= 16000`, and adding `'s'` backward retreat when point-blank (`w * h > 16000`).
Any reappearing candidate or ambiguous frame immediately resets `missing_streak` to `0` and resets `VisualNavigationPolicy`.
When `enable_search=True` or `enable_patrol=True` and a candidate reappears during an active search sweep or visual patrol, `StableAim` immediately releases `'w'`, applies a horizontal search-brake alignment turn (`mouse_dx = max(-16, min(16, error_x * 0.15))`, `search_brake=True`) on the first confirmation frame (`matches == 1`), engages full 2D `track_target` on the second velocity-associated frame (`matches >= 2`), and still requires `matches >= 3` before unlocking `attack` pulses.
When `enable_strafe=True` (`--enable-strafe`), `StableAim` alternates lateral movement keys (`4` frames `'a'` then `4` frames `'d'`) exclusively during confirmed `track_target` frames (`strafe_key` recorded in aim telemetry) and immediately releases all movement keys (`keys=frozenset()`) on `confirm_target`, `post_attack_occlusion`, `missing_target`, `search_target`, or `ambiguous_targets`.
To prevent synthetic gameplay key events from contending with `InputLease.lock` inside the Windows `WH_KEYBOARD_LL` hook thread (`LowLevelHooksTimeout`), `InputOwner.press` and `InputOwner.release_key` ignore non-control keys before acquiring `self.lease.lock`, and `keyboard.Listener` filters low-level hook events to `Esc`, `F8`, and `F9`.
`filter_candidates` also allows upright close-range or lower-leg-occluded Cutman body boxes up to `68%` of the frame area (`0.2 <= w/h <= 1.25`), preventing point-blank targets or targets partially occluded by the player's own Mega Buster sprite from being rejected as `box_extent`.
To support under-fire tracking and damage-triggered counterattacks in `buddha` + `PowerRegeneration` live play without reading engine memory, `measure_damage_cues` extracts two pure visual signals from each `640x480` RGB frame when the top-left HUD border `(47, 30)` and `(47, 120)` is present (`<= 8`): the MM8BDM yellow hit-flash intensity `flash_k` (`min((r + g) // 2)` across dark weapon-outline pixels `b <= 4` and `|r - g| <= 4` in `x in [400, 600), y in [320, 470)`) and the lit HUD health-bar pixel count `hp_pixels` (`x in {50, 52, 58, 60}, y in [20, 150]`).
Whenever `flash_k >= 12`, both `BodyShadowPolicy.predict` (on the GPU tensor before full-frame and local-zoom SSD inference) and `filter_candidates` invert the linear yellow screen blend `RGB = (RGB' - flash_k) / (1 - flash_k / 255)` so yellow-shifted Cutman bodies (such as `(230, 51, 70)` at `flash_k = 51`) retain full detection confidence and magenta appearance ratios without relaxing normal (`flash_k = 0`) thresholds.
When a new hit is detected (`hp_pixels` drops by `>= 3` or `flash_k >= 25` jumps by `>= +15`) while no target is visible, `StableAim` immediately interrupts `patrol_target` or `search_target` and enters a bounded `32`-frame high-speed `counter_search` sweep (`Action(mouse_dx=24 * search_direction)`), widening horizontal tracking to `24 px/frame`, vertical pitch tracking to `16 px/frame` (`160 * dt` when `enable_patrol=True`), and post-brake association to `max(144, 2.0 * max(w, pw))` so the policy brakes (`search_brake=True`), locks `track_target`, and counter-fires as soon as the attacker enters the FOV.
To eliminate the `[0.50, 0.80)` score dead zone between `refine_with_local_zoom` (`0.50`) and `filter_candidates` (`0.80`) and prevent alternating walk-cycle dropouts at medium-far range, `BodyAimPolicy` sets `zoom_accept_score = 0.8` and passes `tracker.previous` (when fresh within `200 ms`) as `hint_box` to `refine_with_local_zoom`, cropping a `320x320` window around the prior tracked box whenever full-frame SSD has no `>= 0.20` proposal.
`BodyShadowPolicy` prewarms both the full `480x640` frame shape and the `320x320` local-zoom crop shape on CUDA (and alternates both shapes across idle `keep_ready` warmups), normalizes `uint8` frame tensors directly on the GPU, slices the GPU full-frame tensor directly inside `refine_with_local_zoom`, caches `SSD` default anchor boxes per feature-map grid, and reuses the decoded RGB frame across `BodyShadowPolicy`, `BodyAimPolicy`, and diagnostic PNG output.

## Export a portable Colab GPU bundle

Export a self-contained `.tar.gz` bundle from any PK3 stack and reviewed background recording:

```bash
PYTHONPATH=src .venv/bin/python -m vimm8bdm.colab_bundle export \
  --packages .local/wads/MM8BDM-v6a.pk3 .local/wads/classes-v9fh.pk3 .local/wads/gondolapatchv2.7h2.pk3 \
  --initial .local/perception/torchvision/ssdlite320_mobilenet_v3_large_coco-a79551df.pth \
  --recording .local/recordings/background-session \
  --frames 0 76 153 230 307 384 461 538 \
  --train-count 512 --validation-count 128 \
  --output .local/bundles/cutman-occlusion-bundle.tar.gz
```

To package an existing reviewed mixed dataset (`data/cutman-real-mixed-3`) with the `v6a` + Gondola stack, augment its training split with foreground occluders extracted from the PK3 stack (`--augment-occluders`), and start from an existing transfer checkpoint:

```bash
PYTHONPATH=src .venv/bin/python -m vimm8bdm.colab_bundle export \
  --packages .local/wads/MM8BDM-v6a.pk3 \
             .local/wads/classes-v9fh.pk3 .local/wads/gondolapatchv2.7h2.pk3 \
  --initial .local/weights/projectile-transfer-model.pt --initial-transfer \
  --dataset data/cutman-real-mixed-3 --augment-occluders 64 \
  --output .local/bundles/cutman-v6a-mixed-bundle.tar.gz
```

The exported archive contains `dataset/`, `initial/checkpoint.pt`, `upright_bank/bank.json`, `occluder_bank/occluders.json`, `colab_manifest.json`, `src/vimm8bdm/`, and a standalone `train_colab.py` script.
It excludes raw `.pk3` and `.vrec` archives so it can be uploaded directly to Google Drive or a Colab session.

## Run GPU training on Google Colab or local CUDA

Inside a Google Colab GPU runtime (A100, L4, or T4) or on a local CUDA machine, run training directly from the `.tar.gz` archive:

```bash
PYTHONPATH=src python3 -m vimm8bdm.colab_bundle train \
  --bundle cutman-occlusion-bundle.tar.gz \
  --output trained-detector \
  --device cuda --epochs 8 --batch-size 16 --learning-rate 0.0005
```

Or unpack the archive and run the bundled script:

```bash
tar -xzf cutman-occlusion-bundle.tar.gz
python3 train_colab.py --output trained-detector --device cuda --epochs 8 --batch-size 16
```

`train_from_bundle` checks every SHA256 digest in `colab_manifest.json` before starting SGD, rejects unsafe archive paths, writes `trained-detector/model.pt` and `trained-detector/colab_bundle_provenance.local.json`, and produces a checkpoint compatible with `BodyShadowPolicy` and `BodyAimPolicy`.
